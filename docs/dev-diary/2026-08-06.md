## 00:49 — Fix ghost voice peers: leave() now closes the signaling WS

**Category:** fix
**Affected files:**
- `crates/lumen-voice/src/signaling.rs`
- `crates/lumen-voice/src/client.rs`
- `crates/lumen-voice/Cargo.toml`
- `crates/lumen-voice/examples/leave_repro.rs`
- `apps/backend/src/do/ChannelDO.ts` (dedup, pre-existing uncommitted — deployed via wrangler)

**Summary:**
Two client bugs left ghost peers ("disconnected" tiles) after leaving/re-joining a voice channel: (1) `leave()` never closed the WebSocket — the heartbeat task holds a clone of the outbound sender, so the writer never saw the channel close; the DO therefore never broadcast `peer-left`. Fixed with a `SignalOut::Close` variant: the writer aborts the reader task and tears down the socket (dropping both split-stream halves is what closes the TCP). (2) `ServerMessage::PeerLeft` lacked `rename_all = "camelCase"`, so the DO's `{"peerId": ...}` failed to parse and the event was silently dropped. Also: `VoiceClient::join` now replaces a session whose run_loop ended on its own (socket death), fixing auto-reconnect which previously retried forever with "already in a voice channel". Verified live against production (leave_repro PASS, peer-left delivered) and backend smoke suite; deployed `lumen-backend` (version 89e8a4bd) with the DO dedup.
